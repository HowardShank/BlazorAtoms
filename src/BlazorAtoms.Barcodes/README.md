# BlazorAtoms.Barcodes

Barcode and QR code **generation** for Blazor, rendered as pure inline SVG. Also **decodes** QR
images the consumer supplies (via ZXing.Net + ImageSharp, in-process). Works in Server or
WebAssembly and every render mode. Three components:

- **`AtomBarcode`** — linear (1D) barcodes: **Code 128**, **EAN-13**, **UPC-A**, **Code 39**,
  **Interleaved 2 of 5 (ITF)**, **Codabar**.
- **`AtomQrCode`** — QR codes (2D matrix): byte/8-bit mode, versions 1–40 (auto-selected to fit the
  data), all four error-correction levels (L/M/Q/H). Full designer styling: module shape, finder-
  eye style, solid or gradient colors, centre logo, outer frame with "SCAN ME" banner.
- **`AtomQrCodeImage`** — displays a QR image the developer supplies (URL / data URI / `byte[]`)
  and optionally decodes it in-process to wrap itself in an anchor when the payload is a URL.

Optional in-browser features (Copy/Save clipboard + download, clipboard-paste of a QR image)
lazily import a small JS module — invisible to consumers, no setup, no `<script>` tag.

## Install

```xml
<ProjectReference Include="..\BlazorAtoms.Barcodes\BlazorAtoms.Barcodes.csproj" />
```
```razor
@using BlazorAtoms.Barcodes
```

Rendering itself is pure C# / `MarkupString`. The optional JS module
(`_content/BlazorAtoms.Barcodes/atom-barcode.js`) is imported on demand only when the consumer
calls `CopyAsync` / `SaveAsync` / `GetPngBytesAsync` on the generators, or displays an
`AtomQrCodeImage` with `AutoLink` / `OnDecoded` engaged.

## Blazor Server tuning (recommended)

`CopyAsync` / `SaveAsync` on the generators are safe — the PNG never crosses SignalR (a one-shot
JS function does svg → canvas → clipboard/download entirely in the browser). `GetPngBytesAsync`
and `AtomQrCodeImage`'s clipboard-paste flow do send image bytes back to the server, and the
default Blazor Server SignalR ceiling of **32 KB** closes the circuit on anything larger.

Add the following to your Blazor Server (or Blazor Web App Interactive Server) `Program.cs`:

```csharp
builder.Services.AddSignalR(options =>
{
    options.MaximumReceiveMessageSize = 5 * 1024 * 1024; // 5 MB
});
```

Trade-offs: only relevant for **client → server** SignalR messages. Slightly larger DoS surface;
negligible on internal / localhost tooling. If your Blazor Server app is public-facing, size the
ceiling to your actual payload needs (500 KB usually covers clipboard image paste).

## Click-to-follow (all three components)

Wraps the code in an `<a>` when a URL is available.

- `Href` — explicit URL. Wins over `AutoLink`.
- `AutoLink` (default `false`) — inspect `Value` (or, for the viewer, decode the image) and wrap
  only when the payload parses as `http:` / `https:` / `mailto:` / `tel:`. Rejects
  `javascript:` / `data:` / `file:` outright.
- `LinkTarget` (default `"_blank"`) — anchor `target=`.
- `rel="noopener noreferrer"` is **always** emitted and is not consumer-configurable. QR payloads
  are a hostile input vector — opener isolation is a hard requirement.

## Decoder (`AtomQrCodeImage`)

Decode runs entirely in .NET via **ZXing.Net + SixLabors.ImageSharp** — no browser API dependency,
identical behaviour across Chrome, Edge, Firefox, and Safari desktop / mobile.

Pipeline: `ImageSharp` loads PNG/JPEG/GIF/BMP/WebP bytes → flattens transparency onto white →
`RGBLuminanceSource` (with alpha-composite fallback per pixel) → `BarcodeReaderGeneric` with
`TRY_HARDER` + `AutoRotate` + `TryInverted`. Multi-strategy: (1) pure barcode read for
clean-rasterized QRs, (2) general read with all hints, (3) grayscale + b/w threshold to defeat
canvas anti-aliasing seams, (4) 2× upscale for tiny clipboard screenshots.

Decode only runs when the consumer opts in — either `AutoLink="true"` or an `OnDecoded` handler.

`AtomQrCodeImage.LastDecodeDiagnostic` surfaces the reason when decode returns null
(`"ImageSharp couldn't decode the bytes …"`, `"no QR code detected (ZXing gave up …)"`, etc.),
so consumers can debug specific images rather than seeing a silent failure.

Decode failures are expected on non-standard finder-eye shapes generated by third-party tools
(rhombus/star/dotted eyes break the 1:1:3:1:1 ratio ISO-18004 requires). This library's own
`EyeFrame` enum is restricted to `Square`, `Circle`, `Rounded` — all decoder-friendly.

## AtomBarcode

```razor
<AtomBarcode Value="BLAZORATOMS-123" Symbology="BarcodeSymbology.Code128" />

@* EAN-13 — pass 12 digits and the check digit is computed for you *@
<AtomBarcode Value="590123412345" Symbology="BarcodeSymbology.Ean13" />

@* Styled, no human-readable text line *@
<AtomBarcode Value="A1234B" Symbology="BarcodeSymbology.Code39"
             Height="80" ModuleWidth="3" Color="#0f172a" Background="#ffffff"
             ShowText="false" QuietZone="12" />
```

Invalid input for the chosen symbology (wrong character set, wrong digit count, bad check digit)
doesn't throw into the render tree — the component catches the encoding error and renders a small
dashed-border error tile containing the message instead.

### Symbologies (`BarcodeSymbology`)

| Value | Accepts | Check digit |
|---|---|---|
| `Code128` *(default)* | Any ASCII 32–126 (Code Set B) | Mod-103, computed automatically |
| `Ean13` | 12 digits (check computed) or 13 digits (check validated) | Mod-10 |
| `UpcA` | 11 digits (check computed) or 12 digits (check validated) | Mod-10 |
| `Code39` | `0-9 A-Z - . space $ / + %` (letters are upper-cased automatically) | None |
| `Itf` (Interleaved 2 of 5) | Digits only (an odd count gets a leading `0`) | None |
| `Codabar` | `0-9 - $ : / . +`, optionally framed by `A`/`B`/`C`/`D` guards (added automatically if missing) | None |

### `AtomBarcode` parameters

| Parameter | Type | Default | Notes |
|---|---|---|---|
| `Value` | `string` (required) | — | Data to encode. Validity rules depend on `Symbology` (see table above). |
| `Symbology` | `BarcodeSymbology` | `Code128` | Which linear symbology to render. |
| `Height` | `double` | `60` | Bar height in px (excludes the human-readable text line). |
| `ModuleWidth` | `double` | `2` | Width of the narrowest bar/space module, in px. |
| `QuietZone` | `int` | `10` | Quiet-zone width on each side, in narrow modules (spec minimum is 10). |
| `Color` | `string` | `#000000` | Bar (and text) color — any CSS color. |
| `Background` | `string?` | `null` | Background fill. `null` leaves the SVG transparent. |
| `ShowText` | `bool` | `true` | Show the human-readable value beneath the bars. |
| `SvgClass` | `string?` | `null` | Extra CSS class(es) on the generated `<svg>` element itself (not the wrapping `<div>` — use `CssClass` for that). |

Plus the shared escape hatch on every Atom component (from `AtomComponentBase`): `CssClass`, `Style`,
and arbitrary splatted attributes (`title`, `data-*`, `id`, ARIA, event handlers, …) on the root `<div>`.

The rendered SVG carries `role="img"` and an `aria-label` of `"Barcode: {Value}"`.

## AtomQrCode

```razor
<AtomQrCode Value="https://example.com" />

@* Higher error correction, custom size and colors *@
<AtomQrCode Value="https://example.com" Size="240" EcLevel="QrErrorCorrection.H"
            Color="#111827" Background="#ffffff" QuietZone="4" />
```

The QR version (1–40) is chosen automatically — the smallest version whose data capacity fits the
UTF-8 byte length of `Value` at the requested `EcLevel`. Longer values, or higher EC levels (which
trade capacity for damage tolerance), push the version up. If the value is too long to fit any
version at that EC level, the component renders an error tile instead of throwing.

### Error correction (`QrErrorCorrection`)

| Value | Approx. recovery |
|---|---|
| `L` | ~7% |
| `M` *(default)* | ~15% |
| `Q` | ~25% |
| `H` | ~30% |

## Notes

- **Output.** Generators (`AtomBarcode`, `AtomQrCode`) render inline `<svg>` (via `MarkupString`)
  inside a wrapping `<div>`. `AtomQrCodeImage` renders a supplied `<img>`. The raw `Value` text is
  HTML-encoded before being placed in `aria-label` / `<text>`, so untrusted input is safe.
- **Cancellation.** All three components honour the shared `CancellationToken` — cancellation
  mid-render produces no output rather than a partial one.
- **Decoding is opt-in.** `AtomQrCodeImage` only invokes the ZXing.Net + ImageSharp pipeline when
  `AutoLink="true"` or an `OnDecoded` handler is wired. Consumers who never opt in still pull the
  NuGet references (they are used by the internal decoder facade), but the pipeline never runs.
- **Anti-aliasing footgun.** Rasterizing a designer QR to PNG in Chrome can introduce sub-pixel
  hairline seams between merged path runs. `QrImageDecoder` handles this with a grayscale +
  binary-threshold pass, so exporting a designer QR from `AtomQrCode` and re-reading it via
  `AtomQrCodeImage` decodes reliably.
- **Third-party brand logos.** The library ships no bundled brand icons — trademark territory.
  Consumers provide their own via `LogoSrc` or `LogoBytes`, sourced from the brand's own
  press-kit page.
